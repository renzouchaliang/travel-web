# 给 Cloud Codex 的固定发布指令

使用当前 travel-web 仓库与已确认模板 travel-template-v1-r13。输入为附带的 trip-<id>.json，格式以 travel-handoff.schema.json 与《交接手册.md》为准。按以下固定步骤执行，不重新规划旅行、不搜索新景点/餐馆/图片、不改版式。

1. 先按publishAction检查ID：create不得覆盖已有旅行；update必须引用已有旅行；ID冲突时报告，不自动覆盖或改名。同一批多份不同ID资料逐份注册，最后返回每份对应链接。校验 `python3 scripts/validate-travel-handoff.py <JSON路径> --require-ready`。若环境缺少jsonschema，安装校验工具依赖到执行环境，不加入网页前端依赖。Schema通过不代表事实已经核实；不代替前期重新查询。
2. 格式错误、ID/引用错、日期错、起终点顺序错时报告具体字段路径；不要替用户猜值。可选照片/诗/链接/评分缺失允许隐藏或留空。地图缺正确端点时保留交通文字，不画直线补路线。
3. 原样保存交接JSON，并将envelope.trip作为规范化Trip导入；不要把整份envelope当成Trip，不再次使用长沙原始导出专用adapter。固定导入方式为创建 `src/trips/<id>/handoff.json`，在注册入口中导入JSON并注册其trip；类型检查时可显式按Trip解析，结构正确性由前面的Schema和引用校验保证。保留其他已发布旅行。
4. 复用现有TravelTemplateV1、地图适配器与Worker。显示字段和缺失行为依照template-contract.json。标题中文天数、日期切换、每日图色诗、短餐饮名、卡片和按钮顺序均沿用既有实现，不临时重设计。
5. 图片只引用提供的URL。若采集端漏填已知坐标的地图位置链接，允许按现有高德URI格式机械生成位置链接，这不代表查找或挑选地点；不为未知坐标生成假链接。
6. 不打印、不提交、不重新索取高德安全码。复用既有公开构建变量与Cloudflare Worker Secret。源码只保留变量名和读取逻辑，不写真实服务端密钥。发布其他域名/账号需要另外配置，不能假定可直接迁移。
7. 构建并验证：npm ci、npm run build；浏览器检查日期/页头、地图选择/图层/全屏退出、卡片/餐饮/探索链接和手机底部四按钮。无真实高德联网条件时明确区分模拟验证与真人地图验证，不称所有实时线路已查实。
8. 用户已授权发布本次资料后提交并推送既有main，等待Cloudflare自动构建成功，再核对线上资料和返回URL。未给部署授权时，先完成所有校验和可审阅预览，最后再请求发布许可。不要把“准备好了”说成“已上线”。

仅在确实影响发布且无法安全省略的问题上请用户补充。不要让用户为每张图片或每个模块重复确认。页面给同行人使用，不展示内部来源、评分查询元数据、开发说明或凭据信息。
